Plugin contracts

The signatures, data types and capabilities of the five plugin kinds, generated from the code.

This page is generated from src/oaken/plugins/contracts.py and src/oaken/plugins/base.py, so it always matches the code. For a walkthrough, see Writing a plugin.

The plugin API version is 2. A plugin whose api_version differs is rejected at load.

PluginJobHandler

One job kind a plugin offers. kind is the plugin's local name (recount); core namespaces it to plugin.<name>.<kind>. payload_model and result_model are pydantic models: the payload is validated before the handler runs, and a result (if result_model is set) is validated and stored, exactly as for a core job kind. concurrency caps how many run at once ([jobs] kind_limits still wins). A plugin enqueues its kind with ctx helpers added later; for now core and other plugins can enqueue it by its namespaced name.

Protocols

A plugin satisfies a contract by having these members.

LLMAccess

The one way a plugin reaches a language model: a PromptBuilder task about mail, as UntrustedText parts. Core picks the workspace from the account, enforces what it allows, answers a repeated question from its cache and validates the answer against the task's schema. A plugin never sees a backend, a database or a workspace.

async def generate_cached(self, builder: 'PromptBuilder[Any]', *parts: UntrustedText, content_hash: str, account_id: str | None=None, message_id: str | None=None, model: str | None=None) -> Any

Plugin

Lifecycle, shared by every kind. All three are optional for a plugin to define.

async def start(self, ctx: PluginContext) -> None

Acquire resources. Raising marks the plugin unhealthy; core carries on.

async def stop(self) -> None

Release resources. Called once at shutdown.

async def health(self) -> Health

A cheap liveness check, polled periodically by the host.

Provider

A mail source or a way to send. Capabilities: auth, sync.pull, flags.write, send. A provider declares at least sync.pull or send: a send-only provider (an SMTP server) has no mail to pull.

async def authenticate(self, ctx: PluginContext) -> None

Make sure the plugin can talk to the service (capability auth).

def pull(self, cursor: str | None, folder: str | None=None) -> AsyncIterator[PullBatch]

Yield batches of changes since cursor (None: from the start). Capability sync.pull. Re-pulling from the last cursor returns nothing new. folder limits the pull to one folder, for a provider with folders (set supports_folders = True); the cursor is still the account's whole cursor, and a folder pull only moves that folder's part of it. Core passes folder only to a provider that supports it, and only when the user scheduled that folder on its own.

async def set_flags(self, provider_ids: Sequence[str], add: Collection[str], remove: Collection[str]) -> None

Write flags back to the server (capability flags.write).

async def send(self, raw_bytes: bytes) -> str

Send a message and return its provider id. Declared for the future; unimplemented in v1, and the host never routes sending to a plugin (capability send).

VectorStore

Stores vectors and finds the nearest ones.

async def upsert(self, items: Sequence[VectorItem]) -> None

Insert or replace by (message_id, chunk_id). Raises if an item's model or dimensions differ from what the store already holds, leaving the store unchanged.

async def delete(self, message_ids: Sequence[str]) -> None

Remove every vector of these messages.

async def query(self, vector: Sequence[float], k: int, filters: dict[str, str] | None=None) -> list[Hit]

The k nearest, best first. filters may name account_id and model_id; a store that sits beside the index may take more (thread_key, after, before, sender) and must refuse a filter it does not know rather than ignore it. Raises if vector does not match the stored dimensions.

async def stats(self) -> VectorStats

How many vectors, and which model and dimensions they use.

CacheOps

The LLM answer cache's members. Core's built-in SQLite cache has them too (it is not a plugin). Core hands over the facts of a question; the cache owns the key.

def key(self, *, workspace: str, task: str, content_hash: str, model: str, prompt_version: str) -> tuple[str, ...]

The key for this question. model is the model that will answer it, never a backend's default: two models must not share a key.

async def get(self, key: tuple[str, ...]) -> CacheEntry | None

The stored answer, or None. A miss costs one model call; raising counts as a miss.

async def put(self, key: tuple[str, ...], entry: CacheEntry) -> None

Store entry. Raising loses the cache write, never the answer.

async def stats(self, workspace: str | None=None) -> CacheStats

What the cache holds (one workspace's, or all).

async def clear(self, workspace: str | None=None, task: str | None=None) -> int

Forget answers (one workspace's and/or one task's, or all). How many were removed.

Cache

An LLM answer cache plugin.

Base classes

Optional. They supply defaults so a plugin overrides only what it does.

BaseProvider

Override pull (a mail source) or send (a sender) at least. Add authenticate and set_flags as the service allows. Capabilities come from what you override (pull is sync.pull, set_flags is flags.write). To state them yourself, set capabilities = frozenset({...}); the host rejects a capability whose method you did not write.

Set:

  • kind: ClassVar[PluginKind] = 'provider'
  • supports_folders: ClassVar[bool] = False
  • account_defaults: ClassVar[dict[str, Any]] = {}

Override:

The @enricher decorator

def enricher(name: str, *, version: str='1', needs_llm: bool=False, output: type[BaseModel] | None=None) -> Callable[[Callable[[EnrichInput], Awaitable[object]]], type[BaseEnricher]]

Turn one async function into an enricher class, ready to register as an entry point: class Result(BaseModel): words: int @enricher("word-count", output=Result) async def word_count(msg: EnrichInput) -> Result: return Result(words=len(msg.body.unwrap().split())) The function may return the model, a dict or an EnrichOutput; the host coerces it.
