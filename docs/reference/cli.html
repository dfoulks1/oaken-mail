CLI

Every `oaken` command, its options and the exit codes — generated by walking the real command-line parser.

The oaken command is a thin client over the local core: every command is one call to a registry operation. It holds no logic of its own, so a new operation is reachable immediately through the generic oaken operation NAME fallback, with no new release. oaken operation NAME takes the operation's own fields as flags (--describe lists them), and oaken PLUGIN VERB is shorthand for oaken operation PLUGIN.VERB, so a function a plugin offers is a command the moment it is installed.

Output is human-readable by default; --json gives the machine form on stdout (never sanitized — it is the contract a script reads), while logs and errors go to stderr. Text printed to a terminal is stripped of control and escape sequences, because mail is untrusted.

1

Global options

These work before or after the command name:

  • --json — emit machine-readable JSON instead of text.
  • --url URL — base URL of a running core (dev override).
  • --token-file PATH — read the API token from this file (dev override).
  • --verbose, -v — show core log output on stderr (-v INFO, -vv DEBUG).

Exit codes

Code Meaning When
0 ok The command succeeded.
1 error The operation ran and failed, or an unexpected error.
2 usage Bad arguments.
3 core down Core is not running — start it with "oaken start".
4 auth A bad API token, or a provider that needs re-authorizing.
5 needs confirmation A mutation returned a proposal and was not confirmed.

Command details

start

Start the core daemon (in the background; --fg to stay attached).

Options:

  • --debug — DEBUG logging for this command, to the terminal and the configured logfile.
  • --fg — Run in the foreground, logging to this terminal (default: the background).

stop

Asks core to stop, waits for it to finish what it is doing (up to --grace seconds), and kills it if it is still running. Core's work is a durable queue, so a killed core loses nothing: unfinished jobs are retried when it starts again.

Options:

  • --debug — DEBUG logging for this command, to the terminal and the configured logfile.
  • --grace — How long core gets to finish what it is doing before it is killed (default 40; 0 kills it at once).
  • --no-kill — Report an error if core does not stop in time, instead of killing it.

restart

Restart the core daemon (in the background; --fg to stay attached).

Options:

  • --debug — DEBUG logging for this command, to the terminal and the configured logfile.
  • --fg — Run in the foreground, logging to this terminal (default: the background).
  • --grace — How long core gets to finish what it is doing before it is killed (default 40; 0 kills it at once).
  • --no-kill — Report an error if core does not stop in time, instead of killing it.

reload

Signals the running core (SIGHUP) to re-read its configuration and rebuild itself in the same process. An invalid file changes nothing.

Options:

  • --debug — DEBUG logging for this command, to the terminal and the configured logfile.

operation

Call a registry operation directly. The input is JSON on --json-input or stdin. This reaches every operation the daemon offers, including ones added after this CLI was released. 'oaken operation' with no name lists the operations. The operation's own fields can be given as flags built from its input schema (see --describe), e.g. 'oaken operation list_messages --limit 5'; 'oaken PLUGIN VERB' is a shorthand for 'oaken operation PLUGIN.VERB'.

Arguments:

  • name — Operation name; omit to list operations.

Options:

  • --debug — DEBUG logging for this command, to the terminal and the configured logfile.
  • --json-input — The operation input as a JSON object. Use '-' or omit to read stdin when piped.
  • --no-browser — Print an address, never open it.
  • --timeout — When an operation waits on the person (a sign-in), give up after S seconds.
  • --describe — Show the operation's summary and input and output fields instead of calling it.
  • --yes — Confirm a mutating operation (the person asked for exactly this).

search

Hybrid search: keyword and vector results merged by rank. Operators in the query: from:, before:, after:, label:, in:, -term, "phrase", term*. Each hit says which retriever found it; if the vector side was down the result says so.

Arguments:

  • query — Search terms and operators.

Options:

  • --debug — DEBUG logging for this command, to the terminal and the configured logfile.
  • --from — Only this sender.
  • --since — Only after this date (ISO 8601).
  • --before — Only before this date (ISO 8601).
  • --label — Only messages carrying this label.
  • --account — Restrict to one account.
  • --disposition — inbox, archive or discarded (discarded is explicit).
  • --category — Only this triage category.
  • --min-priority — Only this priority or more.
  • --unread — Only unread messages.
  • --keyword — Keyword search only (no model, no vectors).
  • --limit — Maximum results.
  • --offset — Skip this many (paging).
  • --starred — Only starred messages.
  • --has-attachment — Only messages with an attachment.

pipeline

Default shows status. 'pause'/'resume' stop and restart the model-bound ingest stages (embed, enrich), or just one (oaken pipeline pause enrich) — mail keeps landing and being filtered while paused. 'limits enrich 2' changes how many jobs a stage runs at once, live. 'parked' re-queues failed ingest jobs.

Arguments:

  • subcommand — status (default), pause, resume, limits, or parked.
  • STAGE — With pause/resume: one stage (embed or enrich), or none for all. With limits: a stage and a number.

Options:

  • --debug — DEBUG logging for this command, to the terminal and the configured logfile.
  • --why — A note recorded with a pause.
  • --retry — With 'parked': re-queue this one parked job.
  • --all — With 'parked': re-queue every parked ingest job.

usage

  • --since-hours — Only the last H hours of usage.
  • --workspace — Only this workspace.

plugins

Plugin control is core's, all here. Default lists plugins; --check runs the health probe now. 'disable' stops a plugin until 'enable' (or a restart; enabled = false in [plugins.NAME] makes it last). 'reload' restarts one on the current config.toml. 'config NAME' shows its settings. 'set NAME KEY=VALUE ...' changes them (--unset KEY, --replace, or --file FILE for TOML; comments in config.toml are kept, secrets are refused). 'check NAME [KEY=VALUE ...]' tries settings on a throwaway instance and writes nothing.

Arguments:

  • subcommand — list (default), enable, disable, reload, config, check or set.
  • name — The plugin (gmail) or one account (gmail@work).
  • KEY=VALUE — With set/check: settings.

Options:

  • --debug — DEBUG logging for this command, to the terminal and the configured logfile.
  • --check — Run each plugin's health probe.
  • --unset — With set/check: remove a setting.
  • --replace — With set/check: KEY=VALUE is the whole table.
  • --file — With set/check: the plugin's settings as TOML (- is stdin).

Arguments:

workspaces

Workspaces are named confidentiality levels: each has a trust level (secure or insecure) and an LLM backend. A secure workspace only uses a local backend. Default lists workspaces. 'get NAME' shows one. 'check NAME [TOML...]' validates without saving. 'set NAME [TOML...] [--file FILE]' creates or replaces. 'remove NAME' removes it (default cannot be removed).

Arguments:

  • subcommand — list (default), get, check, set, or remove.
  • name — The workspace name.
  • TOML — With check/set: TOML lines for the workspace settings (e.g. 'trust = "insecure"').

Options:

  • --debug — DEBUG logging for this command, to the terminal and the configured logfile.
  • --file — With check/set: a TOML file for the workspace settings (- for stdin).

mcp

Reads MCP messages on stdin and forwards them to the MCP server inside the running core, writing its answers to stdout. It adds nothing: the tools, the confirmation step and the limits are core's. If core is not running, tool calls answer with a core_not_running error. It never starts core. Point a stdio-only client (Claude Desktop) at 'oaken mcp'. 'oaken mcp expose' lists which operations MCP clients may call; 'oaken mcp expose NAME on|off|default' (--plugin for a plugin's operations) changes it.

Arguments:

  • action — expose: choose which operations MCP clients may call (bare 'oaken mcp' is the bridge).
  • NAME — With expose: an operation name.
  • state — With expose NAME: on, off, or default (the operation's own).

Options:

  • --debug — DEBUG logging for this command, to the terminal and the configured logfile.
  • --timeout — Give up on a call after.
  • --agent — Speak to the swarm door as an agent (token from OAKEN_AGENT_TOKEN).
  • --agent-token-file — Read the agent token from a file.
  • --plugin — With expose: NAME is a plugin (all of its operations).
