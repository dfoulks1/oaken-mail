CLI

Every `oaken` command, its options and the exit codes — generated by walking the real command-line parser.

The oaken command is a thin client over the local core: every command is one call to a registry operation. It holds no logic of its own, so a new operation is reachable immediately through the generic oaken operation NAME fallback, with no new release.

Output is human-readable by default; --json gives the machine form on stdout (never sanitized — it is the contract a script reads), while logs and errors go to stderr. Text printed to a terminal is stripped of control and escape sequences, because mail is untrusted.

1

Global options

These work before or after the command name:

  • --json — emit machine-readable JSON instead of text.
  • --url URL — base URL of a running core (dev override).
  • --token-file PATH — read the API token from this file (dev override).
  • --verbose, -v — show core log output on stderr (-v INFO, -vv DEBUG).

3

Exit codes

Code Meaning When
0 ok The command succeeded.
1 error The operation ran and failed, or an unexpected error.
2 usage Bad arguments.
3 core down Core is not running — start it with "oaken start".
4 auth A bad API token, or a provider that needs re-authorizing.
5 needs confirmation A mutation returned a proposal and was not confirmed.

Command details

start

Start the core daemon (foreground; --detach for background).

Options:

  • --detach — Run in the background.

stop

Stop the core daemon.

No arguments.

restart

Restart the core daemon.

Options:

  • --detach — Run in the background.

operation

Call a registry operation directly. The input is JSON on --json-input or stdin. This reaches every operation the daemon offers, including ones added after this CLI was released. 'oaken operation' with no name lists the operations.

Arguments:

  • name — Operation name; omit to list operations.

Options:

  • --json-input — The operation input as a JSON object. Use '-' or omit to read stdin when piped.
  • --describe — Show the operation's summary and input and output fields instead of calling it.
  • --yes — Confirm a mutating operation (the person asked for exactly this).

status

Is core running? (does not start it)

No arguments.

search

Hybrid search: keyword and vector results merged by rank. Operators in the query: from:, before:, after:, label:, in:, -term, "phrase", term*. Each hit says which retriever found it; if the vector side was down the result says so.

Arguments:

  • query — Search terms and operators.

Options:

  • --from — Only this sender.
  • --since — Only after this date (ISO 8601).
  • --before — Only before this date (ISO 8601).
  • --label — Only messages carrying this label.
  • --account — Restrict to one account.
  • --disposition — inbox, archive or discarded (discarded is explicit).
  • --category — Only this triage category.
  • --min-priority — Only this priority or more.
  • --unread — Only unread messages.
  • --keyword — Keyword search only (no model, no vectors).
  • --limit — Maximum results.

show

Show one message (cleaned text, or --raw/--headers).

Arguments:

  • message_id — The message id.

Options:

  • --raw — Include the raw bytes (base64 in --json).
  • --headers — Show only the raw headers.

summarize

Summarize messages with the local model.

Arguments:

  • ID — One or more message ids.

Options:

  • --mark-read — Also mark the summarized messages read.

read

Mark messages read.

Arguments:

  • ID — One or more message ids.

Options:

  • --yes — Confirm a bulk change (>25 messages).

unread

Mark messages unread.

Arguments:

  • ID — One or more message ids.

Options:

  • --yes — Confirm a bulk change (>25 messages).

undo

Undo a read-state change from the audit log.

Arguments:

sync

Sync an account (or one folder) now.

Options:

  • --account — Account to sync; default is all.
  • --folder — One folder; default is the whole account.
  • --wait — Wait until the sync job finishes.
  • --timeout — Give up waiting after S seconds.

ask

Answer a question from the mail, citing the messages.

Arguments:

  • question — The question to answer.

Options:

  • --timeout — Give up waiting for the answer after S seconds (a local model can be slow).

pipeline

Default shows status. 'pause'/'resume' stop and restart the model-bound ingest stages (embed, enrich) — mail keeps landing and being filtered while paused. 'parked' re-queues failed ingest jobs.

Arguments:

  • subcommand — status (default), pause, resume, or parked.

Options:

  • --why — A note recorded with a pause.
  • --retry — With 'parked': re-queue this one parked job.
  • --all — With 'parked': re-queue every parked ingest job.

usage

Options:

  • --since-hours — Only the last H hours of usage.
  • --workspace — Only this workspace.

mcp

Reads MCP messages on stdin and forwards them to the MCP server inside the running core, writing its answers to stdout. It adds nothing: the tools, the confirmation step and the limits are core's. If core is not running, tool calls answer with a core_not_running error. It never starts core. Point a stdio-only client (Claude Desktop) at 'oaken mcp'.

Options:

  • --timeout — Give up on a call after.
  • --agent — Speak to the swarm door as an agent (token from OAKEN_AGENT_TOKEN).
  • --agent-token-file — Read the agent token from a file.

admin

Administration: add and inspect accounts.

admin account

Mail accounts.

admin account list

List accounts.

No arguments.

admin account show

One account and its settings.

Arguments:

  • account_id —
admin account add

Asks for the provider, an id, a name and the provider's own non-secret settings, then stores them. The credential is stored afterwards with 'oaken auth'. Give --provider, --id and --name (and --set) to skip the questions.

Options:

  • --provider — gmail, smtp or imap.
  • --id — a-z, 0-9, - and _.
  • --name — A display name.
  • --set — A provider setting (repeatable).

auth

gmail opens Google's consent and waits; smtp and imap read the password without echo. Nothing is ever printed, taken as an argument, or written to disk: the credential goes to the OS keyring.

Arguments:

  • provider —

Options:

  • --account — The account (default: the only one).
  • --check — Check the stored credential only.
  • --password-stdin — Read the password from one line of stdin.
  • --no-browser — Only print the Gmail address.
  • --timeout — Gmail: give up after S seconds.

schedule

When each account syncs. 'set' takes 'every 15m' or a five-field cron expression; edits are audited and take effect live. Editing a schedule is never offered over MCP.

schedule list

Every schedule and its state.

Options:

  • --crontab — Also print a read-only crontab export.

schedule set

Create or change a schedule.

Arguments:

  • account_id — The account to schedule.
  • schedule — 'every 15m' or a five-field cron expression (UTC-aware).

Options:

  • --folder — A per-folder schedule (default: account).
  • --timezone — e.g. America/New_York (unchanged if omitted).
  • --quiet — Mute alerts in this window; sync still runs.
  • --clear-quiet — Remove the quiet window.
  • --run-now — Also sync immediately.

schedule pause

Pause a schedule.

Arguments:

  • account_id — The account to schedule.

Options:

  • --folder — A per-folder schedule (default: account).
  • --why — A note recorded with the pause.

schedule resume

Resume a paused schedule.

Arguments:

  • account_id — The account to schedule.

Options:

  • --folder — A per-folder schedule (default: account).

schedule remove

Remove a schedule.

Arguments:

  • account_id — The account to schedule.

Options:

  • --folder — A per-folder schedule (default: account).
