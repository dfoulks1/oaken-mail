Operations

Everything a client can ask Oaken Mail to do, with its permission class and MCP exposure, generated from the registry.

Every operation, defined once. The general API, the CLI and the MCP server are generated from the same registry. How it works.

Permission: read changes nothing, mutate asks for confirmation, send is refused in this version. MCP is the ceiling in code and the default; the user can lower it, and raise it only up to the ceiling. Marks read means it may change read state.

Inputs and outputs

A trailing ? marks an optional field.

ask

Every quote is checked against the message it cites; claims that fail are dropped, and with none left the answer is insufficient_evidence. Never marks anything read.

  • Input: account_id?, label?, from?, after?, before?, disposition?, question, thread_key?
  • Output: answer, message_ids?, citations?, confidence?, insufficient_evidence?, dropped_claims?, degraded?, degraded_reason?, evidence_tokens?, full_body_tokens?, content_is_untrusted?, warnings?

authorization_status

How an interactive authorization is going.

  • Input: account_id
  • Output: state, detail?

check_account

Check the account's credential: connect, require TLS and log in. Sends and reads nothing.

  • Input: account_id
  • Output: ok, detail?

create_account

Add an account. Its credential is stored separately with set_account_password or start_authorization.

  • Input: account_id, provider, display_name, config?
  • Output: account_id, provider, display_name, config, problem?, config_schema?

create_agent

The swarm must be enabled and every kind listed in [swarm] allowed_kinds.

  • Input: label, kinds, account_ids?, max_leases?, max_per_hour?
  • Output: agent, token

enrich_message

Run the enrichers on one message now.

  • Input: message_id, enrichers?, force?
  • Output: message_id, ran, cached, results

get_account

One account: provider, its non-secret settings, what the provider's settings are, and why it cannot sync if it cannot.

  • Input: account_id
  • Output: account_id, provider, display_name, config, problem?, config_schema?

get_enrichment

Show the stored enrichment results (summary, triage, actions, inspector) for a message.

  • Input: message_id, enricher?
  • Output: message_id, results, content_is_untrusted?

get_message

The cleaned text (quotes and signatures removed), cut to the caller's limit. Reading a message here does not change read state: only opening or summarizing it, by the user, does.

  • Input: message_id, include_text?, text_chars?
  • Output: message_id, account_id, thread_key?, subject?, from_addr?, from_name?, date?, labels?, disposition?, is_read?, indexed?, text?, truncated?, attachments?, content_is_untrusted?

get_message_rules

How a message was filed: its labels, flags and disposition, and the rule behind each.

  • Input: message_id
  • Output: message_id, attrs, filter?

get_raw

The raw headers of a message, and optionally its raw bytes, for inspection. Not for MCP.

  • Input: message_id, include_raw?
  • Output: message_id, size_raw, in_lfs, headers, raw_base64?, truncated?

list_accounts

The configured accounts: id, provider and display name (never credentials).

  • Input: none
  • Output: accounts

list_agents

List the registered agents (never their tokens).

  • Input: include_revoked?
  • Output: agents

list_audit

The newest audit-log rows: who changed what, why, and whether it can be undone.

  • Input: limit?, op?
  • Output: entries

list_labels

Every label and disposition with how many live messages carry it.

  • Input: none
  • Output: labels, dispositions, content_is_untrusted?

list_messages

Newest first. Snippets by default; include_text adds the cleaned text within the reply's character budget. Never marks anything read.

  • Input: account_id?, label?, from?, after?, before?, disposition?, limit?, include_text?, text_chars?
  • Output: items, truncated?, content_is_untrusted?, warnings?

list_operations

Every operation with its permission class, and whether MCP clients may call it.

  • Input: none
  • Output: operations

list_plugins

Every plugin: kind, version, capabilities, health, the operations it offers, its settings.

  • Input: name?
  • Output: plugins

list_schedules

Every sync schedule: when it next runs, how the last run went, and whether it is paused.

  • Input: crontab?
  • Output: schedules, crontab?

mark_read

Mark messages read. Written back to the mailbox; undoable.

  • Input: ids, after_summary?
  • Output: changed, unchanged, missing, local_only, audit_ids, batch_id?, skipped?

mark_unread

Mark messages unread. Written back to the mailbox; undoable.

  • Input: ids, after_summary?
  • Output: changed, unchanged, missing, local_only, audit_ids, batch_id?, skipped?

message_dismissed

The user stopped looking before the delay passed: cancel the pending mark.

  • Input: message_id
  • Output: cancelled

message_presented

The user is looking at this message: core marks it read after the configured delay.

  • Input: message_id
  • Output: armed

pause_schedule

Pause a sync schedule until it is resumed.

  • Input: account_id, folder?, why?
  • Output: schedule

pipeline_status

Where ingest stands: each stage's queue, throughput and ETA, and jobs parked as failed.

  • Input: none
  • Output: stages, docs, chunks, index_stale, vector_model?, vectors, embedder_model?, embeddings_stale, backfill_paused, quarantined_files, parked?

plugin_health

Whether plugins are started and healthy, and why not if they are not.

  • Input: name?
  • Output: plugins

rebuild_index

Rebuild the search index from the raw store (resumable).

  • Input: account_id?, force?
  • Output: job_id, created

remove_schedule

Remove a sync schedule (a per-folder one, or an account's, which stops its sync).

  • Input: account_id, folder?
  • Output: removed

reprocess

Bring one pipeline stage up to date for old mail (parse, filter, embed or enrich).

  • Input: stage, account_id?
  • Output: job_id, created

resume_schedule

Resume a paused sync schedule: it is due now and its failure count is cleared.

  • Input: account_id, folder?
  • Output: schedule

revoke_agent

Revoke an agent at once; the jobs it holds go back to the queue.

  • Input: agent_id
  • Output: revoked

search

Each hit says which retrievers found it (why). When the embedder or the vectors are unavailable the keyword results still come back, with degraded set. Never marks read.

  • Input: account_id?, label?, from?, after?, before?, disposition?, query, limit?, thread_key?, category?, min_priority?, unread_only?
  • Output: items, truncated?, content_is_untrusted?, warnings?, degraded?, degraded_reason?

search_keyword

Hits come back with the matching words marked **like this**. Never marks read.

  • Input: account_id?, label?, from?, after?, before?, disposition?, query, limit?
  • Output: items, truncated?, content_is_untrusted?, warnings?

set_account_config

Replace an account's non-secret settings.

  • Input: account_id, config
  • Output: account, restart_needed

set_account_password

Store an account's password in the OS keyring (SMTP and IMAP). It is never shown again.

  • Input: account_id, password
  • Output: stored

set_operation_exposure

Choose whether MCP clients may call an operation, or all of a plugin's operations.

  • Input: scope, name, mcp
  • Output: scope, before, after, operations

set_schedule

Create or change a sync schedule. The floor and the timezone are checked now.

  • Input: account_id, folder?, schedule, timezone?, quiet?, clear_quiet?, run_now?
  • Output: schedule

sieve_check

Compile a Sieve script and report the first error, with its line.

  • Input: script, name?
  • Output: ok, error?, line?, requires?, sha256?

sieve_list

List the Sieve scripts on disk, and any skipped with the reason.

  • Input: none
  • Output: enabled, directory, sha256, scripts, problems

sieve_test

Run a Sieve script on one message and show each effect and its rule. Stores nothing.

  • Input: script, name?, message_id?, eml_base64?
  • Output: check, disposition?, rule?, effects?, errors?, steps?

start_authorization

Begin an interactive consent (Gmail). Returns the address to open; poll authorization_status.

  • Input: account_id
  • Output: url

status

A short health summary: accounts, messages, index, queue, plugins and paused schedules.

  • Input: none
  • Output: version, accounts, messages, indexed, index_stale, queue_depth?, plugins_healthy?, plugins_total?, schedules_paused?

summarize_message

Summaries are cached by content and model, and made in the message's own workspace (a secure one never reaches a remote model). Mail text goes to the model only as UntrustedText. A message that cannot be summarized says why and does not stop the others. Read state changes only if mark_read is true, and only for the ones that got a summary.

  • Input: message_ids, mark_read?
  • Output: items, marked_read?, content_is_untrusted?

sync_now

Sync an account (or one folder) now. Joins a sync already queued or running.

  • Input: account_id, folder?
  • Output: job_id, created

undo

Undo a read-state change from the audit log, restoring exactly what each message was.

  • Input: audit_id
  • Output: changed, unchanged, missing, local_only, audit_ids, batch_id?, skipped?

usage_summary

Model calls and tokens per workspace, stage and model, and what the cache saved.

  • Input: since_hours?, workspace?
  • Output: rows

Plugin operations

A plugin may offer more, named <plugin>.<name>. They are listed by list_operations at run time, and are always off over MCP until the user turns them on.
