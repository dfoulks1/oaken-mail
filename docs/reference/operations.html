Operations

Everything a client can ask Oaken Mail to do, with its permission class and MCP exposure, generated from the registry.

Every operation, defined once. The general API, the CLI and the MCP server are generated from the same registry. How it works.

Permission: read changes nothing, mutate asks for confirmation, send is refused in this version. MCP is the ceiling in code and the default; the user can lower it, and raise it only up to the ceiling. Marks read means it may change read state.

Inputs and outputs

A trailing ? marks an optional field.

ask

Every quote is checked against the message it cites; claims that fail are dropped, and with none left the answer is insufficient_evidence. Never marks anything read.

  • Input: account_id?, label?, location?, from?, after?, before?, disposition?, unread_only?, starred?, has_attachment?, thread_key?, question
  • Output: answer, message_ids?, citations?, confidence?, insufficient_evidence?, dropped_claims?, degraded?, degraded_reason?, evidence_tokens?, full_body_tokens?, content_is_untrusted?, warnings?

cancel_job

Cancel a queued job, or ask a running one to stop at its next safe point.

  • Input: job_id
  • Output: job_id, status

check_plugin_config

Test one plugin's settings before saving them: they are checked against the plugin's own schema and capabilities, then a throwaway instance is started on them and asked if it is healthy. Give no change to test the saved settings. The running plugin is not touched and nothing is written.

  • Input: plugin, text?, config?, unset?, replace?, kind?
  • Output: ok, problems?, probes?

config_get

Read the current config.toml text (non-secret; tokens are never stored here).

  • Input: none
  • Output: path, text, exists

config_reload

Reload core on the saved config.toml (the Reload button). Core rebuilds in place: the old config is restored automatically if the new one fails to start. Watch /v1/health to see it come back (the port may change).

  • Input: none
  • Output: ok, requested, error?

config_save

Validate and save config.toml, backing up the previous file (the Save button). Does not reload core; call config_reload to apply.

  • Input: text
  • Output: ok, path, backup?, error?

config_validate

Test an edited config.toml against the settings schema without saving it (the Test button).

  • Input: text
  • Output: ok, error?

create_account

Add an account. Its credential is stored separately by the provider's own auth command (for example gmail.auth).

  • Input: account_id, provider, display_name, config?
  • Output: account_id, provider, display_name, config, receive_only?, capabilities?, problem?, config_schema?

create_agent

The swarm must be enabled and every kind listed in [swarm] allowed_kinds.

  • Input: label, kinds, account_ids?, max_leases?, max_per_hour?
  • Output: agent, token

create_folder

Make a folder under Inbox, and any folders above it. A path that already exists is fine.

  • Input: path
  • Output: path, created

create_label

Make a label (a tag for finding mail). A label that already exists is fine.

  • Input: name
  • Output: name, created

enrich_message

Run the enrichers on one message now.

  • Input: message_id, enrichers?, force?
  • Output: message_id, ran, cached, results

get_account

One account: provider, its non-secret settings, what the provider's settings are, and why it cannot sync if it cannot.

  • Input: account_id
  • Output: account_id, provider, display_name, config, receive_only?, capabilities?, problem?, config_schema?

get_enrichment

Show the stored enrichment results (summary, triage, actions, inspector) for a message.

  • Input: message_id, enricher?
  • Output: message_id, results, content_is_untrusted?

get_message

The cleaned text (quotes and signatures removed), cut to the caller's limit. Reading a message here does not change read state: only opening or summarizing it, by the user, does.

  • Input: message_id, include_text?, text_chars?
  • Output: message_id, account_id, thread_key?, subject?, from_addr?, from_name?, date?, labels?, disposition?, location?, is_read?, starred?, to_addrs?, cc_addrs?, message_id_header?, in_reply_to?, references?, indexed?, text?, truncated?, attachments?, content_is_untrusted?

get_message_rules

How a message was filed: its labels, flags and disposition, and the rule behind each.

  • Input: message_id
  • Output: message_id, attrs, filter?

get_plugin_config

Read one plugin's settings: its [plugins.NAME] table, the schema of its settings and an example to start from. Non-secret only.

  • Input: plugin
  • Output: plugin, exists, config, text?, config_schema?, config_example?

get_raw

The raw headers of a message, and optionally its raw bytes, for inspection. Not for MCP.

  • Input: message_id, include_raw?
  • Output: message_id, size_raw, in_lfs, headers, raw_base64?, truncated?

get_thread

Ask by any message id or by thread key. parent_id is the message it replies to (the nearest ancestor we hold when its direct parent never arrived); a message that answers nothing we have is a root. Never marks anything read.

  • Input: message_id?, thread_key?, limit?
  • Output: thread_key, items?, total?, truncated?, content_is_untrusted?, warnings?

list_accounts

The configured accounts: id, provider and display name (never credentials).

  • Input: none
  • Output: accounts

list_agents

List the registered agents (never their tokens).

  • Input: include_revoked?
  • Output: agents

list_audit

The newest audit-log rows: who changed what, why, and whether it can be undone.

  • Input: limit?, op?
  • Output: entries

list_jobs

The newest jobs in the durable queue, with their status, attempts and any scrubbed error.

  • Input: status?, kind?, account_id?, limit?
  • Output: jobs

list_labels

Every label, folder (location) and disposition with how many live messages carry it.

  • Input: none
  • Output: labels, dispositions, locations, unread?, content_is_untrusted?

list_mailbox

The sidebar: Inbox and Discarded, the folder tree under Inbox, and labels, each with how many messages are in it and how many are unread. Empty folders and labels are included.

  • Input: none
  • Output: inbox, discarded, folders, labels, content_is_untrusted?

list_messages

Newest first unless sort says otherwise. Snippets by default; include_text adds the cleaned text within the reply's character budget. Never marks anything read.

  • Input: account_id?, label?, location?, from?, after?, before?, disposition?, unread_only?, starred?, has_attachment?, thread_key?, limit?, offset?, sort?, include_text?, text_chars?
  • Output: items, truncated?, offset?, total?, total_exact?, content_is_untrusted?, warnings?

list_operations

Every operation with its permission class, and whether MCP clients may call it.

  • Input: none
  • Output: operations

list_plugins

Every plugin: kind, version, capabilities, health, the operations it offers, its settings.

  • Input: name?
  • Output: plugins

list_schedules

Every sync schedule: when it next runs, how the last run went, and whether it is paused.

  • Input: crontab?
  • Output: schedules, crontab?

mailbox_counts

The sidebar's numbers in one call: Inbox, Starred and Discarded, every folder (location) and every label, each with how many messages and how many are unread. No mail content.

  • Input: account_id?, include_discarded?
  • Output: inbox?, starred?, discarded?, locations?, labels?, content_is_untrusted?

mark_read

Mark messages read. Written back to the mailbox; undoable.

  • Input: ids, after_summary?
  • Output: changed, unchanged, missing, local_only, audit_ids, batch_id?, skipped?

mark_unread

Mark messages unread. Written back to the mailbox; undoable.

  • Input: ids, after_summary?
  • Output: changed, unchanged, missing, local_only, audit_ids, batch_id?, skipped?

message_dismissed

The user stopped looking before the delay passed: cancel the pending mark.

  • Input: message_id
  • Output: cancelled

message_presented

The user is looking at this message: core marks it read after the configured delay.

  • Input: message_id
  • Output: armed

move_to_folder

File messages into a folder under Inbox (made if new), or back into the Inbox. The person's choice beats a Sieve rule's.

  • Input: ids, path?
  • Output: path, moved

pause_backfill

Pause the model-bound ingest stages (embed, enrich), or just one with stage. Mail keeps landing and being filtered; a running job finishes. It survives a restart.

  • Input: why?, stage?
  • Output: llm_paused, reason?, paused_stages?

pause_schedule

Pause a sync schedule until it is resumed.

  • Input: account_id, folder?, why?

pipeline_status

Where ingest stands: each stage's queue, throughput and ETA, and jobs parked as failed.

  • Input: none
  • Output: stages, docs, chunks, index_stale, vector_model?, vectors, embedder_model?, embeddings_stale, backfill_paused, llm_paused?, quarantined_files, parked?

plugin_disable

Stop a plugin and keep it off until plugin_enable or a restart, without reloading core. Put enabled = false in the plugin's [plugins] table to make it last.

  • Input: name
  • Output: changed, plugins

plugin_enable

Start a plugin that plugin_disable stopped. A plugin whose table says enabled = false stays off until that line is removed and the plugin is reloaded.

  • Input: name
  • Output: changed, plugins

plugin_health

Whether plugins are started and healthy, and why not if they are not.

  • Input: name?
  • Output: plugins

plugin_reload

Restart one plugin on the current config.toml (and pick up a plugin installed since boot) without reloading core.

  • Input: name
  • Output: changed, plugins

rebuild_index

Rebuild the search index from the raw store (resumable).

  • Input: account_id?, force?
  • Output: job_id, created

remove_account

Remove an account and its sync schedules. Stored mail is kept; the credential is dropped.

  • Input: account_id
  • Output: removed, schedules_removed?, restart_needed?, mail_kept?

remove_schedule

Remove a sync schedule (a per-folder one, or an account's, which stops its sync).

  • Input: account_id, folder?
  • Output: removed

  • Input: stage, account_id?, since?, limit?
  • Output: job_id, created

Resume the model-bound ingest stages after a pause, or just one with stage.

  • Input: stage?
  • Output: llm_paused, reason?, paused_stages?

Resume a paused sync schedule: it is due now and its failure count is cleared.

  • Input: account_id, folder?

retry_job

Re-queue a failed or cancelled job to run now, clearing its last error.

  • Input: job_id
  • Output: job_id, status

retry_parked

Re-queue one parked ingest job, or with all=true every parked ingest job, to run again.

  • Output: retried

revoke_agent

  • Input: agent_id
  • Output: revoked

savings_summary

Tokens saved, by caller: model calls the cache skipped, and mail text kept out of a client's context. Estimates.

  • Input: since_hours?

search

search_keyword

Hits come back with the matching words marked **like this**. Never marks read.

  • Input: account_id?, label?, location?, from?, after?, before?, disposition?, unread_only?, starred?, has_attachment?, thread_key?, query, limit?, offset?, sort?
  • Output: items, truncated?, offset?, total?, total_exact?, content_is_untrusted?, warnings?

Plugin operations

A plugin may offer more, named <plugin>.<name> (a provider's login, say). They are listed by list_operations at run time, are always off over MCP until the user turns them on, and are reachable from the CLI as oaken <plugin> <name> (or oaken operation <plugin>.<name>, with one flag per input field). A plugin declares one with the @command decorator in oaken.plugins.base.

Plugins installed with this version, and the functions each offers. A plugin you install yourself adds its own, which show up on your machine, not here.
