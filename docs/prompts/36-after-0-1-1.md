# 36 — After 0.1.1: the follow-ups

**Read first:** `docs/prompts/00-context.md` and [35 — onboarding](35-onboarding-0-1-1.md).

These are the things 0.1.1 deliberately left, each sized to be its own session. They are *not*
0.1.x work: 0.1.1 was "no new features". Where one overlaps a numbered prompt, that prompt is the
spec and this is the reminder.

| Item | What | Notes |
|---|---|---|
| Label and folder write-back | Optionally mirror labels and folders to Gmail (and folders to IMAP) | Configured in the **provider plugin's** table, not core. Core keeps the queue, the audit and undo and asks the provider (a `labels.write` capability). Stars already write back through `flags.write`. |
| Workspace routing by Sieve rule | A Sieve rule decides which workspace (and so which datastore, embedder and vector partition) a message goes to | A core mapping. Example: mail a Sieve script marks sensitive goes to a higher-security workspace than day-to-day mail. Spec: prompt 31. |
| A datastore per account | Each account gets its own datastore and enrichment database | `oaken mailbox` is the natural CLI view of one; today the store is shared and `--account` filters. |
| Send and sync | `send_message` as a `send` job on the queue; sync also runs sends waiting out a retry delay; receive-only never sends | Spec: prompt 28. |
| Gmail without the Cloud Console | A sign-in modal in the web console, a `gmail doctor` check, then (a separate decision) a vendor OAuth client | The default stays bring-your-own client; do not re-litigate the ceiling, see the Gmail section of 35. |
| Start plugins lazily or concurrently | Plugins start one after another, so a slow model plugin (a cold Ollama) can delay core by up to 30 seconds, and tests that wait 30 seconds flake | Start them concurrently, or only when something first needs them. Found when Ollama was cold under load; it showed again as a 26-second start. |
| The web UI settings page | Wire `config.html` to `get_plugin_config`, `check_plugin_config`, `set_plugin_config`, `plugin_enable`, `plugin_disable`, `plugin_reload` | The operations take an editor's TOML (`text`), keep its comments, and keep `enabled` and `capabilities` apart for a switch and chips. Prompt 23 is the spec. |
| Model management | List the models installed in Ollama, choose the model for the enrichers and for `ask`, and install new ones from oaken (`oaken ollama models`, `oaken ollama pull`), so nobody has to know the Ollama CLI | Wanted by Drew. Design open: the commands belong to the Ollama plugin; where a per-enricher or per-command model setting lives, and a progress view for a pull, need deciding. |
| Security pass | Prompt 19 was never run | Include the remote bind, per-account command dispatch and password handling. |
| Flaky retrieval eval | `test_a_rerun_gives_the_same_numbers` fails about one run in four, on the pre-0.1.1 code too | The report's context-token total differs by a few tokens between runs. Likely ranking ties between messages whose ids are random within a millisecond (UUIDv7); break ties on something stable. |
| Offline Bootstrap | Vendor Bootstrap so the console works with no network | Parked: you need the network to install Oaken anyway. |
