# 05 — `raw.db`: the source of truth

**Read first:** `docs/prompts/00-context.md`. **Depends on:** 02 (and shares the DB with 03).

## Goal

Durable storage for raw mail: compressed content-addressed RFC 822 blobs plus the
provider bookkeeping needed to sync. Nothing derived lives here.

## Requirements

1. **Migrations:** one ordered migration set for `raw.db` (the jobs table from 03 is
   migration `0001`; yours continue the sequence). Do not fork the runner.
2. **Schema** (`raw.db`):
   - `accounts(id, provider, display_name, created_at, config_json)` — one used for now.
   - `blobs(sha256 PRIMARY KEY, size_raw, size_stored, codec, data BLOB)`; codec `zstd`
     (add `zstandard` dependency); content-addressed, so identical messages dedupe.
   - `messages(id, account_id, provider_id, blob_sha256 → blobs, internal_date,
     first_seen_at, deleted_at NULL, UNIQUE(account_id, provider_id))`.
   - `message_state(message_id, is_read, is_starred, labels_json, server_updated_at,
     local_dirty_json)` — **read-state intent** columns used by prompt 12.
   - `sync_cursors(account_id, scope, cursor, updated_at)`.
3. **`RawStore` API** (async): `put_message(account_id, provider_id, raw, meta) ->
   (MessageId, is_new)`, `get_raw(message_id) -> bytes`, `mark_deleted(…)`,
   `iter_messages(account_id, since=…)`, cursor get/set, `stats()`. `put_message` is
   idempotent and transactional; it **verifies** the sha256 on read when asked
   (`verify=True`) and raises `StorageError` on corruption.
4. **Large messages:** stream compress/decompress; a configurable hard cap
   (`storage.max_message_bytes`, default 100 MB) beyond which a message is stored as a
   header-only stub with a `truncated` marker — never crash the pipeline.
5. **Safety:** DB files are created `0600`; the module has an explicit
   "never log message bodies" test (log capture asserts no body text appears).
6. **Emit** `MessageStored(message_id, is_new)` via the event bus after commit
   (inject the bus; no global).

## Acceptance criteria

- Round-trip: arbitrary bytes (including invalid UTF-8, huge headers, NUL bytes) come
  back identical; identical raw bytes from two provider IDs share one blob.
- Corruption test: flip a byte in a stored blob → `verify=True` raises.
- Idempotency: `put_message` twice with the same provider ID → one row, `is_new` False
  the second time; changed raw bytes (same provider ID) produce a new blob and update
  the pointer, with the old blob retained until a documented `gc_blobs()` removes unreferenced ones.
- Deleting is a soft delete (`deleted_at`), and `gc_blobs()` never removes a referenced blob.
- Property test (hypothesis, add as dev dep) for the compress/decompress round trip.

## Out of scope

Parsing (06), the index (07), real providers.

## Checkpoint

Standard report. Include the compression ratio on a synthetic 1,000-message corpus
generated by a fixture helper (no real mail).

## Built differently

- **Large messages are never truncated.** Instead of a header-only stub with a `truncated`
  marker, a message over `storage.inline_max_bytes` (8 MiB) is written whole to an **LFS folder**
  (`lfs/`, one zstd file per blob), and `raw.db` keeps a link and a small header stub.
  `storage.max_message_bytes` (100 MiB) now only decides when the `LargeMessageStored` event is
  marked `oversize`. `blobs` gained `stub` and `lfs_path`, and `messages` has no `truncated`
  column.
- **Events.** `MessageStored` gained `is_new` and `changed`, and a repeat put publishes nothing.
  `LargeMessageStored` is new. Plugins can define events by subclassing `PluginEvent` and
  calling `ctx.publish` (see `docs/plugins.md`).
- **Accounts** have a create/get/list/set-config API. Config is non-secret only, and secret-looking
  keys are refused.
- **Database files** are created owner-only before SQLite opens them, so `-wal` and `-shm`
  inherit the mode. This applies to every database, not just `raw.db`.
